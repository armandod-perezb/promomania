📌 Cambio 1: Actualización del modelo Promocion
Ubicación: models/promocion.dart

Qué cambié: Añadí un nuevo campo booleano fotoEsLocal para poder diferenciar si el string en foto es una URL de internet o un nombre de archivo local guardado en el dispositivo.

Cambios específicos:

En la definición de la clase, agregué:

El campo final bool fotoEsLocal; justo después del campo foto

Lo declaré como opcional en el constructor con valor por defecto false

En el constructor, añadí el parámetro:

this.fotoEsLocal = false

En el método fromJson, agregué la línea:

fotoEsLocal: json['foto_es_local'] as bool? ?? false,

Esto asegura que si el JSON no tiene ese campo, asume false (es decir, es una URL remota)

En el método toJson, agregué la línea:

'foto_es_local': fotoEsLocal,

En el método copyWith, añadí el parámetro:

bool? fotoEsLocal,

Y en el return: fotoEsLocal: fotoEsLocal ?? this.fotoEsLocal,

Propósito: Este campo me permite saber, cuando voy a mostrar una imagen, si debo leerla del sistema de archivos local (usando ImageStorageService) o si debo descargarla desde una URL remota.

📌 Cambio 2: Adición de métodos de gestión de imágenes al PromoService
Ubicación: services/promo_service.dart

Qué cambié: Añadí múltiples métodos y variables para manejar el ciclo de vida completo de las imágenes de las promociones.

2.1. Nueva variable de instancia:
dart
final ImageStorageService _imageStorage = ImageStorageService();
Propósito: Crear una instancia del servicio de almacenamiento de imágenes para poder guardar, leer y eliminar imágenes locales.

2.2. Método savePromotionImage:
dart
Future<String?> savePromotionImage(String codigoPromocion, Uint8List bytes)
Qué hace este método:

Recibe el código de la promoción y los bytes de la imagen

Valida que los bytes correspondan a una imagen real (no HTML, no texto)

Genera un nombre único para el archivo usando el código de promoción más timestamp

Guarda la imagen usando ImageStorageService.saveImageFromBytes()

Actualiza la promoción correspondiente en la lista promociones con el nuevo nombre de archivo

Notifica a los listeners para que la UI se actualice

Guarda los cambios en el archivo persistente local usando _saveLocalData()

Almacena los bytes en el caché en memoria _imageCache

Retorna el nombre del archivo guardado o null si hay error

2.3. Método getPromotionImageBytes:
dart
Future<Uint8List?> getPromotionImageBytes(String codigoPromocion)
Qué hace este método:

Busca la promoción por su código

Si no existe o no tiene foto, retorna null

Verifica si la foto es local (usando fotoEsLocal o verificando si el string comienza con "http")

Si es local: llama a _imageStorage.readImageBytes() para leer los bytes del archivo guardado

Si es remota: llama a _downloadAndCacheImage() para descargar y cachear la imagen

Retorna los bytes de la imagen o null si hay error

2.4. Método privado _downloadAndCacheImage:
dart
Future<Uint8List?> _downloadAndCacheImage(String codigoPromocion, String url)
Qué hace este método:

Primero verifica si la imagen ya está en _imageCache para no descargarla nuevamente

Si no está en caché, hace una petición HTTP GET a la URL

Verifica que el status code sea 200 (éxito)

Almacena los bytes en _imageCache usando el código de promoción como clave

Retorna los bytes o null si hay error

2.5. Método privado _isUrl:
dart
bool _isUrl(String str)
Qué hace: Verifica si un string comienza con "http://" o "https://" para determinar si es una URL remota o un nombre de archivo local.

2.6. Método privado _isValidImageBytes:
dart
bool _isValidImageBytes(Uint8List bytes)
Qué hace: Valida que los primeros bytes del array correspondan a los headers de formatos de imagen conocidos (JPEG, PNG, GIF). Esto evita guardar HTML o datos corruptos como imágenes.

2.7. Método preloadPromotionImages (opcional):
dart
Future<void> preloadPromotionImages(List<String> codigosPromocion)
Qué hace: Recibe una lista de códigos de promoción y precarga todas sus imágenes en caché para que la UI sea más fluida al mostrar listas.

📌 Cambio 3: Creación del widget PromocionCard
Ubicación: widgets/promocion_card.dart (nuevo archivo)

Qué cambié: Transformé el _buildPreviewCard() que tenías en un widget reutilizable que recibe una Promocion y usa el PromoService para cargar su imagen.

Estructura del nuevo widget:
Parámetros requeridos:

promocion: el objeto Promocion a mostrar

promoService: la instancia del servicio (generalmente obtenida mediante Provider o pasada como parámetro)

En la sección de la imagen:

Ya no uso Image.network() directamente

Uso un FutureBuilder<Uint8List?> que llama a promoService.getPromotionImageBytes(promocion.codigo)

Estados del FutureBuilder:

Cargando (ConnectionState.waiting): Muestra un CircularProgressIndicator sobre fondo gris

Con datos (snapshot.hasData && snapshot.data != null): Muestra Image.memory() con los bytes obtenidos

Sin datos o error: Muestra el mismo placeholder con gradiente y el icono de imagen

El resto del widget (título, ubicación, overlay degradado) se mantiene igual, pero ahora usa promocion.titulo y promocion.ubicacion directamente

📌 Cambio 4: Ajuste en el método _saveLocalData (importante)
Ubicación: services/promo_service.dart - método _saveLocalData

Qué cambié: Notarás que _saveLocalData NO guarda las imágenes en el JSON, solo guarda los metadatos (los nombres de archivo en el campo foto).

Por qué es importante:

Las imágenes son archivos binarios pesados, no deben guardarse en JSON

El JSON solo contiene foto: "promo_ABC123_1234567890.jpg"

Las imágenes reales se guardan por separado usando ImageStorageService

En web, las imágenes se guardan en localStorage (también por separado)

Esto significa que: Cuando cargas los datos persistentes con loadLocalPromociones(), los nombres de archivo se cargan correctamente, y cuando llamas a getPromotionImageBytes(), el servicio sabe buscar ese archivo en el almacenamiento local.

📌 Flujo completo de cómo funciona ahora
Escenario 1: Guardar una nueva imagen para una promoción
El usuario selecciona una imagen (desde cámara o galería)

Obtienes los bytes de la imagen (Uint8List)

Llamas a promoService.savePromotionImage(codigo, bytes)

El servicio:

Valida que sean bytes de imagen válidos

Genera un nombre único

Guarda físicamente la imagen (en disco/localStorage)

Actualiza el campo foto de la promoción con ese nombre

Marca fotoEsLocal = true

Guarda los metadatos en el JSON persistente

Notifica a la UI

Escenario 2: Mostrar una promoción existente
El widget PromocionCard se construye

El FutureBuilder llama a promoService.getPromotionImageBytes(codigo)

El servicio:

Obtiene la promoción y su campo foto

Determina si es local o remota

Si es local: lee los bytes del almacenamiento

Si es remota: descarga de internet y cachea

Los bytes se pasan a Image.memory() para mostrar

Mientras carga, muestra un indicador de progreso

Escenario 3: Persistencia entre sesiones
Cuando la app inicia, se llama a init() que carga el JSON base

Se llama a loadLocalPromociones() que carga cualquier promoción guardada previamente

Los nombres de archivo en foto se restauran

Cuando se necesita mostrar la imagen, el servicio la encuentra en el almacenamiento local porque el nombre sigue siendo el mismo
